## 1. 我们已有的积累：复盘 `loom-lang` 与 `lang-research`

### 1.1 `loom-lang`：我们实现了什么，以及暴露了什么问题？

`loom-lang` 已经是一套极其扎实、诚实标注边界的工程系统，绝非玩具原型：

- **硬核工程里程碑（已达成）**：
  - **N0 / N1 自举门禁已通过**：三平台（macOS / Linux / Windows）LLVM 22 后端 + Stage 2/3 字节级一致自举。Loom 自身前端（`compiler/std/loom`）达 **146,350 行**，Rust 侧（`compiler/src`）仅保留 **3,226 行** LLVM lowering 与精简 runtime。
  - **强约束与契约落地**：支持标量、记录、元组、枚举、列表上的精化类型（如 `type Amount = Int where self >= 0`、`type OrderedBounds = BoundsRow where self.lower <= self.upper`）；实现了 `requires` / `ensures` / `old()`；`ensures` 必须编译期静态证明（本地规则 + 外部 Z3 求解器），未证明/超时直接阻塞构建（Fail-Closed）。
  - **复杂算法证明跑通**：已能在真实源码上端到端证明排序算法的**相邻有序性 + 全行置换（`ordered` + `permutation`）**，并在证明后自动消除循环中的运行时断言。
  - **工程与工具链生态雏形**：目录即包、同目录私有测试、LSP/VS Code 扩展、格式化器、`std.storage` 精化记录编解码器与 SQLite `CHECK` 派生（PR #968/#969）、语义合并工具 `loom change`（基于 `.loom-ids` sidecar）、离线 SQLite 订单迁移试炼（`tools/deployment`，24,810 行）。

- **深入代码与现状文档后暴露的 4 个结构性张力**：
  1. **【最深层矛盾】默认“共享可变引用 + Moving GC”与形式化验证剧烈冲突**
     - Loom 为了消除 Rust 式所有权/借用语法，选择了普通赋值默认共享可变对象（`var b = a; b[0] = 9` 同步影响 `a`）+ STW Moving GC。
     - 代价在 `implementation-status.md`（1,011 行）中一览无遗：**超过一半的编译器证明基础设施，都在和“可变别名干扰（aliasing interference）、草案发布（draft publication）、分配纪元（allocation epoch）、堆版本失效（heap version invalidation）、回调逃逸”搏斗**。
     - 一旦存在隐式共享可变别名，一个已通过检查的精化值（例如有序数组、非空列表或含可变子结构的记录）随时可能被另一条别名悄悄改坏。为了维持声音性（soundness），编译器不得不堆叠大量脆弱的启发式帧条件分析，前端体积迅速膨胀至 ~15 万行，而通用的可变对象图不变量依然无解。
  2. **验证缺乏分层，编译反馈与证明耗时沉重**
     - Loom 的精化检查、复杂排序置换证明、集合直方图编码都压在同一条单层证明链 + 外部 Z3 进程调用上。据 `compiler/README.md` 实测（2026-10-24，Apple M4 Max），SMT 示例冷检查耗时 **13.465 s**，加上 LLVM 22 代码生成与链接，远未达到 `lang-research` 对标的 **Go/Zig 级开发反馈体验**。
  3. **精化类型的“业务表达力”与“算法证明”重心失衡**
     - 业务开发最日常的刚需（跨字段依赖类型如 `Date` 合法年月日、同余/奇偶/对齐、正则/格式校验、自动派生边界校验与错误路径、流敏感类型细化）需要轻快、可预测、零心智负担的 L0 求解器；而 Loom 投入了巨大精力在共享可变列表上攻克直方图置换证明，导致日常使用门槛和实现复杂度双高。
  4. **系统级演化停留在“三张皮”受限原型**
     - 源码合并靠手工维护 `.loom-ids` sidecar（易丢、易冲突）；
     - 持久化编解码靠手动为精化类型写 `impl ColumnValue`；
     - 版本升级仅做到硬编码 `orders`/`notes` 表结构的离线 SQLite 试炼，`field_implies` 只比对单个字段类型，`hotfix` 判定仍恒为 `Unproven`，**缺乏统一的“跨版本类型精化推导 → 兼容矩阵 → 双向迁移透镜验证 → 在线滚动共存”语言级体系**。

### 1.2 `lang-research`：我们做过哪些一手实验，得出了什么硬结论？

[`lang-research`](../../lang-research) 以“一手固定源码 + 可复现探针 + C/Rust/Go/Zig 基准对照”为纪律，围绕 **正确性、内存安全与效率、系统编程、并发、元编程、编译速度（对标 Go/Zig）与执行速度（对标 Rust/C）** 产出了关键认知：

1. **纯整数原生执行追平 C/Rust 并不难，难的是编译速度 + 内存模型的综合取舍**：
   - 在 M4 Max 5,000 万步 xorshift32 基准中，Gojo（76.2ms）、Goose（76.3ms）、Bend 2（110.7ms，含启动）执行均可接近 C/Rust（75–78ms / 110ms）；但完整构建耗时差异巨大：Go/Zig ~103–145ms，Gojo 172ms，Goose 211ms，Bend 2 903ms，Mojo 1023ms。
2. **“内存安全 + 减少分配 + 降低所有权心智负担”的三者平衡有两条证据最扎实的路线**（`research/memory-models.zh-CN.md`）：
   - **路线 A：Goose 式编译器多数据栈 + 推断引用根 + 紧凑内联**（实测构建 10,000 条变长记录工作区间 0 次 `malloc`），配合虚拟地址预留原地增长（`stack-growth` 与 `go-hybrid-stack` 实验验证了跨平台虚拟内存预留/页归还及无 MMU 分块回退策略）。
   - **路线 B：Koka/Lean 的 Perceus 自动精确引用计数 + 唯一引用原地复用（FBIP）**（实测 Lean 独占链表转换 0 次新节点分配，共享时自动退回按需分配）。
3. **纯区域/数据栈无法消除所有长期图取舍，必须显式界定“长期独立删除”边界**（`beyond-goose.zh-CN.md`、`region-reclamation-designs.zh-CN.md`、`goose-hybrid-gc.zh-CN.md`）：
   - 作用域数据栈极其适合请求、解析、编译阶段、帧计算；
   - 长期可变对象图要么走 **可回收容器 `Store` + 带代句柄 `Handle` + 延迟提交访问阶段 `phase` + 声明式拥有/观察关系**（无 GC 路线），要么走 **自动分类 + 精准非移动 GC 回退**（混合 GC 路线）。

## 2. 最近 1 年（2025 年末 – 2026 年末）全球新语言与关键竞品全景调研

2025–2026 年编程语言界发生了一个历史性拐点：**AI 编程（Vibe Coding）泛滥催生了反向浪潮——Vericoding（可验证编程）**。当 AI 可以秒级生成千行代码时，单元测试不再够用（AI 自己写代码自己写测试等于“自己给自己批卷子”），**强类型约束 + 内置形式化验证 + 显式效应/能力边界 + 极速编译反馈**成为 2026 年所有新语言的共同焦点。

以下按四大阵营系统梳理近 1 年新出现或实现关键质变的语言/工具链，并给出客观优缺点评估：

### 阵营 D：强约束数据建模与 Schema 演化先驱（领域参照）

- **CUE / Pkl / KCL / Nickel**：证明了“精化约束/类型即谓词（如值范围、正则、跨字段 check）”在配置与 API 校验上极具生产力，但在 2026 年它们仍局限于配置语言（CaC），**无法编写业务服务、算法逻辑和原生二进制**。
- **Project Cambria / Schemaboi (`josephg/schemaboi`)**：证明了用 **双向透镜（Bidirectional Lenses）** 可以在多版本 Schema 共存时双向转换数据并保留未知字段。但它们缺乏**编程语言级的精化类型检查和 SMT 形式化证明**，无法在编译期证明“透镜对所有旧数据不崩溃、产物满足新不变量、回滚后不丢数据”。

### 核心定位总结

> **Tenon 不是“又一门更好的 C/Rust 替代品”，也不是“又一个学术定理证明器”。**  
> Tenon 的核心壁垒在于**用同一套数学地基（MVS 值语义 + 精化谓词格 + 分层求解器）同时打通三个原本割裂的领域**：
> 1. **写代码时**：像写 Go/TypeScript 一样流畅，却拥有比 Rust 更强的值域与跨字段不变量约束力（金额正数、奇数、合法 `Date`、状态机）；
> 2. **编译时**：没有共享可变别名爆炸，90% 约束毫秒级静态证明并消除运行时检查，关键契约 Fail-Closed 兜底，天然适配 AI Vericoding 闭环；
> 3. **发布与演化时**：把“改类型/改约束/改表结构/发新版本/灰度共存/回滚再升级”从人肉祈祷变成**编译器可推导、可证明、可执行的系统级协议**。
